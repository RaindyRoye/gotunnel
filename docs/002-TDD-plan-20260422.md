# TDD 计划

## 现状

- 仅有 `auth_test.go` 和 `buffer_test.go` 两个测试文件
- 核心网络/多路复用逻辑（hub、link、conn、server、client）零测试覆盖
- `buffer_test.go` 未测试并发场景（`sync.Cond` 的核心用途）
- 代码直接依赖 `net.Conn`、`net.Dial` 等具体实现，mock 困难
- 全局可变状态（`Heartbeat`、`Timeout`、`LogLevel`）影响测试隔离


## 第四阶段：集成测试

- 启动 Server + Client（同一进程内），走完完整的 tunnel 建立和认证流程
- 验证端到端数据传输正确性和加密一致性
- 测试重连、心跳超时、多 tunnel 负载均衡等场景

## 工具

```
go test -race -cover ./tunnel/    # 竞态检测 + 覆盖率
go test -fuzz                     # Go 1.18+ 原生模糊测试，适合 auth/conn 的编解码
```

不引入第三方测试框架，标准库 `testing` 足够。

## Client 单元测试方案

### 对比 Server

| 维度 | Client | Server |
|---|---|---|
| 纯数据结构 | `HubQueue` 堆实现 | 无 |
| 纯函数 | `backoff()` | 无 |
| Ctrl 过滤 | 心跳接收 → 更新 `rcvd` | `LINK_CREATE` → 建 link + dial backend；`TUN_HEARTBEAT` → echo |
| 状态管理 | `addHub/removeHub/fetchHub/dropHub` + 优先级轮转 | 无 |
| 心跳 | 主动发送 + 超时断开 | 被动 echo，无超时逻辑 |
| 重连 | 指数退避重连 | 无，靠 Client 主动重连 |
| 网络依赖 | `dial()` 连 Server | `DialTimeout()` 连 backend |

Server 的 Tier 1 只有 `ServerHub.onCtrl()` 过滤逻辑，但 `LINK_CREATE` 分支会 `go handleLink(l)` → `net.DialTimeout`，无法在 Tier 1 隔离。Server 的测试重心在 Tier 4 集成，与 Client 合并测试。

### Tier 1：纯函数/数据结构（零依赖）

#### HubQueue 堆操作

| # | 测试 | 验证 |
|---|------|------|
| 1 | `Push` + `Pop` 优先级排序 | priority 最小的先弹出 |
| 2 | `Push` 相同 priority | 保持堆性质，Pop 顺序稳定 |
| 3 | `Swap` 更新 `index` 字段 | Swap 后 item.index 与实际位置一致 |
| 4 | `Remove` 按索引删除 | 删除后堆性质正确，剩余 item.index 正确 |
| 5 | 空 queue `Len` / `Pop` | Len=0，Pop panic 不会发生（heap 层保护） |

直接构造 `HubQueue` slice 即可，无需任何 I/O。

#### backoff() 函数

| # | 测试 | 验证 |
|---|------|------|
| 6 | `attempt=0` → `[baseDelay/2, baseDelay)` | jitter 范围正确 |
| 7 | `attempt=N` → 指数增长 | delay = baseDelay × 2^N |
| 8 | 增长不超过 `maxDelay` | delay ≤ maxDelay |
| 9 | `baseDelay == maxDelay` | 始终返回 maxDelay 范围 |
| 10 | 多次调用 → jitter 不同 | 不是固定值（概率性，跳过极端情况） |

纯函数，直接断言返回值范围。

#### ClientHub.onCtrl() 过滤

| # | 测试 | 验证 |
|---|------|------|
| 11 | `TUN_HEARTBEAT` → `rcvd` 更新 | `h.rcvd == cmd.Id`，返回 true |
| 12 | 非 `TUN_HEARTBEAT` → passthrough | 返回 false，`rcvd` 不变 |

用 `newPipeTunnels()` 构造 ClientHub（嵌入 Hub），直接调用 `onCtrl`。

### Tier 2：内存状态管理（需 pipe tunnel）

#### Client hub 管理

| # | 测试 | 验证 |
|---|------|------|
| 13 | `addHub` → 队列长度递增 | 添加后 `cq.Len()` 正确 |
| 14 | `fetchHub` → 取优先级最低的 item | priority 最小的被选中 |
| 15 | `fetchHub` 后 priority++ | 下次 fetchHub 轮转到其他 item |
| 16 | `dropHub` 后 priority-- | item 重新变成最优先 |
| 17 | `removeHub` → 从堆中删除 | 删除后堆性质正确 |
| 18 | `fetchHub` 空队列 → 返回 nil | 无 panic |
| 19 | `removeHub` 无效 item → 不 panic | index=-1 或已删除 |
| 20 | `dropHub` 无效 item → 不 panic | index=-1 或已删除 |
| 21 | 多轮 `fetchHub` 轮转均衡性 | 3 个 hub 各被选中次数接近 |

构造 `Client`（`NewClient` 不需要网络），HubItem 内的 ClientHub 用 `newPipeTunnels()` + `newClientHub()` 创建。注意 `newClientHub()` 会启动 `heartbeat()` goroutine，测试结束需关闭 tunnel 让其退出。

### Tier 3：heartbeat 逻辑

| # | 测试 | 验证 |
|---|------|------|
| 22 | heartbeat 周期发送 `SendCmd` | peer 收到 TUN_HEARTBEAT，sent 递增 |
| 23 | 收到 echo → `rcvd` 更新 | `sent == rcvd`（短暂延迟后） |
| 24 | 连续未收到 echo → 超时断开 | `Hub.Close()` 被调用，`heartbeat()` 退出 |

临时将全局 `Heartbeat` 设为极短值（如 50ms），`Timeout` 设为 200ms。测试后恢复。需要控制 `newClientHub` 的生命周期 — 关闭底层 tunnel 使 `heartbeat()` 和 `Start()` 退出。

### Tier 4：Client + Server 集成测试

同进程起真实 Server + Client，走完整流程。

#### 测试环境搭建

```
[Client.listen] ← TCP → [Client] ← Tunnel(ChaCha20) → [Server] ← TCP → [backend echo]
```

- backend：localhost TCP echo server（收到什么回什么）
- Server：`NewServer(serverAddr, backendAddr, secret)` + `go s.Start()`
- Client：`NewClient(clientAddr, serverAddr, secret, tunnels)` + `go cli.Start()`

#### 测试矩阵

| # | 测试 | 验证 |
|---|------|------|
| 25 | 端到端数据往返 | 连 Client.listen → 发数据 → 收到相同数据 |
| 26 | 多个并发连接 | 多个 TCP 连接同时转发，数据不错乱 |
| 27 | 认证失败（secret 不匹配） | Client 连不上，重试后也不成功 |
| 28 | Server 关闭 tunnel → Client 重连 | 新连接建立，数据继续转发 |
| 29 | 后端不可达 → LINK_CLOSE | Server dial backend 失败 → 回复 LINK_CLOSE → Client 收到错误 |
| 30 | 多 tunnel 负载均衡 | tunnels=3，多个连接分布在不同 tunnel 上 |

#### 关键设计点

- 集成测试同时覆盖 Client 和 Server，不单独为 Server 写测试文件
- 用 `sync.WaitGroup` + channel 做同步，避免 `time.Sleep`
- backend echo server 极简：`goroutine read + write back`
- 测试结束需关闭 listener 和 tunnel，避免 goroutine 泄漏
