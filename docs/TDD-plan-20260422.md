# TDD 计划

## 现状

- 仅有 `auth_test.go` 和 `buffer_test.go` 两个测试文件
- 核心网络/多路复用逻辑（hub、link、conn、server、client）零测试覆盖
- `buffer_test.go` 未测试并发场景（`sync.Cond` 的核心用途）
- 代码直接依赖 `net.Conn`、`net.Dial` 等具体实现，mock 困难
- 全局可变状态（`Heartbeat`、`Timeout`、`LogLevel`）影响测试隔离

## 第一阶段：纯函数/工具模块

无需重构，投入产出比最高。

| 模块 | 测试内容 |
|---|---|
| `id_allocator.go` | Acquire/Release 正确性、并发安全、ID 耗尽时阻塞、释放后复用 |
| `mpool.go` | Put/Get 往返、容量检查逻辑、并发安全 |
| `buffer.go` | 补充并发读写场景、Close 后 Pop 行为、容量动态增长 |
| `log.go` | 各级别日志输出格式、LogLevel 过滤逻辑 |

## 第二阶段：引入接口抽象

为核心模块测试铺路。

1. `conn.go` 中的 `Tunnel` 依赖 `io.ReadWriter`，可用 `bytes.Buffer` 做测试
2. `hub.go` 的 `onCtrlFilter` 已是扩展点，可注入测试用控制命令
3. 把 `dial()` / `newListener()` 等函数改为可注入的字段（函数类型），便于测试时替换

## 第三阶段：核心模块单元测试

| 模块 | 测试策略 |
|---|---|
| `conn.go` (Tunnel) | 用 `net.Pipe()` 构造成对的读写端，测试加密/解密往返、分包/粘包 |
| `conn.go` (TunnelConn) | 测试 ChaCha20 加解密一致性、帧格式编解码 |
| `hub.go` | 用 mock `Tunnel` 注入控制命令（LINK_CREATE/LINK_CLOSE 等），验证 link 生命周期管理 |
| `link.go` | 用 `net.Pipe()` 模拟双向数据转发，测试 close 语义（半关闭/全关闭） |

## 第四阶段：集成测试

- 启动 Server + Client（同一进程内），走完完整的 tunnel 建立和认证流程
- 验证端到端数据传输正确性和加密一致性
- 测试重连、心跳超时、多 tunnel 负载均衡等场景

## 工具

```
go test -race -cover ./tunnel/    # 竞态检测 + 覆盖率
go test -fuzz                     # Go 1.18+ 原生模糊测试，适合 auth/conn 的编解码
```

不引入第三方测试框架，标准库 `testing` 足够。

## 实施顺序

从第一阶段开始，先为 `id_allocator` 和 `mpool` 写测试，同时补充 `buffer` 的并发测试。
